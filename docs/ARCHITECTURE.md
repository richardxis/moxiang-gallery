# 架构与关键流程

## 数据与权限

MySQL 保存用户、图片元数据、空间、成员、扩图任务、保存幂等记录和对象清理任务。COS 保存图片对象，Redis 与 Caffeine 缓存公共分页结果。

`spaceId = null` 表示公共图库。个人空间由所有者管理，团队空间通过 `space_user` 关联成员并分配 viewer、editor、admin。登录使用 HttpSession，空间权限由 Sa-Token 校验。

## 上传与保存

1. 验证登录、文件类型/大小、空间权限与额度。
2. 上传 COS，获取数据万象解析、压缩与缩略图结果。
3. 数据库事务内重新校验空间、额度与图片版本，提交图片元数据和使用量。
4. 失败时由清理任务补偿上传对象；成功替换后延迟清理旧对象。

协作保存同时验证连接、租约、房间 epoch、草稿版本与持久化 revision。requestId 对应已提交结果，重试可查询原结果。

## 缓存

规范化条件与排序后，使用命名空间、共享数据版本和条件摘要形成键。启用两级缓存时，先读 Redis 共享版本，再查 Caffeine、Redis 页面，未命中时查询 MySQL。缓存不可用时回到数据库。写入提交后清理本实例缓存并切换共享版本，历史键按 TTL 回收。

## 协作

以 pictureId 管理房间。编辑权属于连接，租约 60 秒；编辑动作与续租需要匹配持有人令牌。断线、退出、权限失效和过期均释放编辑权。服务端每 5 秒清扫，90 秒未活动的连接被回收。

旋转与缩放通过 WebSocket 同步，矩形裁剪在前端预览，导出的图片通过 HTTP 保存。图片写入门控协调单图、协作与批量编辑。

## 搜索与批量编辑

以图搜图只提交审核通过的公共图片，依次获取识图页面、列表接口和相似图结果。请求目标固定为服务商域名，链接经过协议校验，返回验证页时提供结果页入口。

颜色搜索使用 RGB 欧氏距离归一化相似度，在授权范围内排序，默认返回前 12 张。批量编辑先按全局顺序获取写入门控，再在事务中锁定空间和图片；全部版本检查通过后才更新元数据。

## 空间分析

空间使用读取使用量计数器；公共/全站使用 COUNT、SUM。分类和图片大小在数据库聚合，标签 JSON 按 ID 游标分批读取；用户趋势按日、ISO 周或月分组。全站排行按空间存储量排序。

## 分享

分享链接指向图片详情页，二维码编码相同链接。公共图片遵循审核可见规则，个人和团队图片继续校验登录及空间权限，不生成匿名授权。
